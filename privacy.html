Privacy Policy

Last updated: 12 November 2026

Operator review required before publication: This page describes common data categories for anti-nuke and moderation bots, but the operator must verify each category against Lexiiee's code and configuration. Complete the storage and retention details below before using this policy for Discord review.

1. Who operates Lexiiee

Lexiiee (the “Bot”) is maintained by its developer or operator. For privacy questions or requests, contact deajaloco@gmail.com.

2. Information Lexiiee may process

Depending on the features a Discord server enables and the permissions or intents granted to the Bot, Lexiiee may process the following categories when needed to provide its functions:

  • Discord identifiers: user IDs, server (guild) IDs, channel IDs, role IDs, and message IDs needed to apply settings, run commands, or identify relevant moderation events.
  • Moderation records: moderation actions (such as warnings, timeouts, kicks, or bans), affected user IDs, moderator or actor IDs, timestamps, reasons entered by moderators, and related case information, if the moderation system records these.
  • Anti-nuke and security events: event types, timestamps, relevant actor and server IDs, and audit-log information received by the Bot to identify unusual changes or potentially destructive activity.
  • Server configuration: protection settings, trusted-user or allowlist entries, thresholds, and other preferences saved by server administrators, if Lexiiee supports persistent configuration.
  • Command and message information: command names and options needed to respond to commands. Message content should only be processed where a specific feature requires it and the Bot is configured and permitted to access it.
  • Technical information: error reports and operational logs used to diagnose failures, if these are enabled and retained.

This list is conditional, not a statement that every category is always collected. The operator must remove categories Lexiiee does not process and add any other categories it does. Check the Python source code, database, configuration, and hosting logs.

3. How information is used

Information may be used to provide Lexiiee's functions, including responding to commands, saving server settings, detecting and reporting unusual server activity, applying administrator-configured anti-nuke protections, recording moderation cases, and troubleshooting or securing the service. The actual purposes must match the features enabled in Lexiiee.

4. Storage and retention

Storage location and method: The operator must specify where Lexiiee's data is stored (for example, local files, SQLite, or another database) and identify the relevant hosting or database provider. The SparkPanel bot-hosting service may also produce operational logs; the operator should check its current logging practices and terms rather than assume what those logs contain.

Retention period: The operator must state how long moderation records, security events, server settings, and technical logs are kept, when they are deleted, and whether server administrators can clear them. Do not publish an invented retention period.

5. Sharing and service providers

Discord processes information in connection with the Discord platform. Information may also be processed by the hosting, database, or monitoring providers actually used to operate Lexiiee. The operator should identify those providers and review their privacy information.

The operator should update this section if Lexiiee uses additional APIs, analytics, logging services, or other integrations. Do not claim that no information is shared unless the Bot's code and all providers have been checked.

6. Access, correction, and deletion requests

For privacy questions or requests about information handled by Lexiiee, contact deajaloco@gmail.com. Include enough detail to identify the relevant server and record, but never send passwords, Discord tokens, or other login credentials.

The operator should review requests and explain any applicable limits, including records that must be retained for security, moderation, or legal reasons. Server owners should also be told how they can remove stored server settings or records when the Bot is removed, where supported.

7. Security

Reasonable safeguards appropriate to the service should be used to protect information. No online service can guarantee absolute security. The operator and server administrators should protect credentials, restrict access to dashboards and databases, and never publish the Bot token or API keys.

8. Changes to this policy

This policy may be updated when Lexiiee's features, providers, or data practices change. The date above will be updated when a revised version is published.

9. Contact

For privacy questions, contact: deajaloco@gmail.com.
